# 指标趋势深化设计（metrics-deepening）

日期：2026-08-06
状态：待用户审查
前置：2026-08-05-p1-metrics-panel.md（原模块设计，本设计在其上深化）

## 背景

指标趋势面板（P1，2026-08-05 加入）从实验记录抽取性能数值绘制趋势图，存在数据治理缺陷：

1. **工艺参数污染**：字段 key 含「温度」即被 temp 指标收走（退火温度 780℃ 会被画成「温度」数据点），实际是工艺条件而非性能结果
2. **裸数字误收**：content 全语料兜底，「3 炉都失败了」的 3 可能被抽走
3. **单位不归一**：Seebeck 380 μV/K 与 0.38 mV/K 画在同一条线上，构成假趋势
4. **温度维度缺失**：ZT=0.9 @ 823K 与 ZT=0.5 @ 300K 混画一条线；一条记录多温度点只抽第一个
5. **体系靠正则猜**：语料命中材料名即归类，content 提到对比文献材料会误判；认不出则堆进「未标注」

用户已拍板的方向（2026-08-06 头脑风暴）：

- 体系识别失败：**不进图但提示**（面板警告条）
- 单位缺失：**空心点但不连线**
- 新增 `analyze_metrics` 对话工具：**工具只查数，呈现交给对话 AI**
- 温度维度：**全局温度筛选器**（多温度点全抽、不同温度深浅区分、温度跳变断线、筛选后连线）
- 单位展示：**基准单位 + tooltip 原始值溯源**
- 体系机制：**显式「材料体系」字段**（表单 + 巡检提案提取，字段优先、正则兜底）

## 一、数据纳入规则（src-server/server/metrics.js 改造）

### 1.1 指标白名单（可画指标，共 7 个）

| key | label | 基准单位 | keyRe（字段键命中） |
|---|---|---|---|
| zt | 热电优值 ZT | 无量纲 | ZT / 热电优值 / figure of merit |
| pf | 功率因子 PF | μW·cm⁻¹·K⁻² | 功率因子 / power factor / PF |
| sigma | 电导率 σ | S·cm⁻¹ | 电导率 / conductivity / σ |
| seebeck | Seebeck 系数 S | μV·K⁻¹ | seebeck / 塞贝克 |
| kappa | 热导率 κ | W·m⁻¹·K⁻¹ | 热导率 / thermal conductivity / κ |
| n | 载流子浓度 n | cm⁻³ | 载流子浓度 / carrier concentration |
| mu | 迁移率 μ | cm²·V⁻¹·s⁻¹ | 迁移率 / mobility |

**移除 temp 指标**：温度不再是可画指标，降级为数据点的「测试条件」属性。

### 1.2 工艺参数黑名单（字段 key 完全匹配即排除，不参与任何提取）

退火温度、生长温度、保温温度、升温速率、降温速率、保温时间、升温时间、降温时间、压力、气氛、电流、电压、转速、加热功率、射频功率、升温、保温、冷却

匹配规则：**完全匹配**（大小写不敏感）。不做包含匹配，避免误杀「测试温度」（性能上下文）。

### 1.3 判定顺序（每个字段依次走，命中即止）

1. 指标白名单 keyRe 命中 → 取该字段值数字，进指标（**优先于黑名单**，保护「功率因子」类字段）
2. 工艺黑名单命中 → 排除
3. 兜底（仅限 entry.data「实验数据」字段）：valueRe 全局匹配，每条匹配抽值 + 温度上下文；**content 完全不参与数字提取**

### 1.4 多温度点全抽

- valueRe 由单次 exec 改为全局匹配（g），一条记录同一指标可产出多个点（如 ZT=0.9 @ 823K 与 ZT=0.5 @ 300K）
- 去重：同记录、同指标、同温度、同值 → 只收一个
- 温度上下文优先级：① 字段名「测试温度 / 温度」的值（记录级）② 指标值附近 ±40 字窗口（extractTemp 保留）
- 抽不到温度 → temp: null，显示「温度未标注」

### 1.5 单位归一化（UNIT_NORM 表，系数已验算）

| 指标 | 基准 | 变体 → 系数 |
|---|---|---|
| sigma | S·cm⁻¹ | S/m ×0.01；mS/cm ×0.001 |
| seebeck | μV·K⁻¹ | mV/K ×1000；V/K ×1e6 |
| kappa | W·m⁻¹·K⁻¹ | mW/(cm·K) ×0.1；W/(cm·K) ×100 |
| pf | μW·cm⁻¹·K⁻² | mW/(m·K²) ×10 |
| n | cm⁻³ | 科学计数法（1e19、1.2×10^19、1.2E19） |
| mu | cm²·V⁻¹·s⁻¹ | m²/(V·s) ×1e4 |

- 值字符串中抽取单位模式，查表换算；查不到 → `unit: null`（空心点、不连线、不参与基准比较）
- 点属性携带 `value`（归一化后）与 `raw`（原始字符串，tooltip 溯源）
- 换算表写死在代码并在此文档列明，不做配置项。换算系数已物理验算：1 μW·cm⁻¹·K⁻² = 0.1 mW·m⁻¹·K⁻²（故 mW/(m·K²) → μW·cm⁻¹·K⁻² 乘 10；SnSe 经典 PF≈10 μW/cmK² ≈ 1 mW/mK² 可对照）

### 1.6 体系识别（字段优先、正则兜底）

1. `entry.system` 字段命中（显式，表单/巡检写入）→ 使用，不再猜测
2. 兜底：SYSTEM_DEFS 扫 **fields 值 + data**（不扫 content，避免「与 SnSe 文献对比」误判体系）
3. 均未命中 → unrecognized（**不进图**），由 GET /metrics/series 返回 `totals.unrecognized` 列表（entryId / date / sampleId / content 摘要）

### 1.7 文献基线（保留 + 温度标注）

- extractLiteratureBaseline 保留（仅 record/peak/最高/创纪录 语境取最大，保守策略不变）
- 增强：顺带抽取基线值的测试温度（baseline.temp / tempUnit），供面板提示「文献基准 @823K vs 你的点 @300K」

## 二、API 返回契约

### GET /metrics/series（扩展）

```jsonc
{
  "metrics": {
    "zt": {
      "key": "zt", "label": "热电优值 ZT", "unit": "",
      "systems": {
        "SnSe": [
          { "date": "2026-08-05", "ts": 1754366400000, "value": 0.9,
            "raw": "ZT=0.9 @ 823K", "unit": null,
            "temp": 823, "tempUnit": "K",
            "entryId": "work_xxx", "sampleId": "S-20260805-01" }
        ]
      },
      "count": 1
    }
  },
  "order": ["zt", "pf", "sigma", "seebeck", "kappa", "n", "mu"],
  "baseline": { "zt": { "value": 2.5, "temp": 823, "tempUnit": "K" } },
  "totals": {
    "entries": 12, "withMetrics": 3,
    "unrecognized": [ { "entryId": "work_yyy", "date": "2026-08-06", "sampleId": "S-20260806-01", "content": "配置 Bi2Te3 单晶生长…" } ]
  }
}
```

- `value` 一律归一化；`unit: null` 表示单位未标注
- 温度集合由面板从各点 `temp` 提取

### analyze_metrics 工具（新增，只读）

- 入参：`metric?`（缺省全部）、`system?`（缺省全部体系）、`temp?`（可选测试温度筛选）、`from?`/`to?`（可选日期范围）
- 返回：与 GET /metrics/series 同构的数据（无 UI 层），AI 依据数据自行组织回答（文本/表格/判断）
- **不做趋势判断**：最新值/Δ/点数等统计由工具给出原始序列与简单统计，上升/下降结论由对话 AI 基于点数谨慎表述，点数 < 3 时明示「样本不足」
- 遵循工具只读纪律，不产生提案、不写库

## 三、面板改造（ui/panels/MetricsPanel.tsx + ui/components/MetricsChart.tsx）

### 3.1 温度筛选器

- 面板顶部 chips：「全部温度」+ 数据中实际出现的温度值集合（如 823K、300K）
- 筛选后：只画该温度的点，同体系点连线（此时趋势可比）
- 「全部温度」态：同体系不同温度点用**同色系不同明度**区分（温度越高越深），相邻点温度不同则**断开线段**；图例标注「温度跳变处断线」

### 3.2 空心点

- `unit === null` 的点：空心圆，tooltip 注明「单位未标注，未参与连线与基准比较」；不连接前后线段

### 3.3 tooltip 溯源

- 归一值（基准单位）、原记录值（raw）、测试温度、样品号、记录日期、内容片段（前 40 字）

### 3.4 未识别体系警告条

- `totals.unrecognized.length > 0` 时面板顶部显示：「⚠️ N 条实验记录未识别材料体系」
- 点击展开列表（日期 + 样品号 + 内容摘要），每条右侧「✏️ 补标注」按钮 → 切换到实验记录 tab 并打开该条编辑弹窗（WorklogPanel 支持外部传入 targetEntryId 预载编辑）
- 未识别记录不进图、不计入任何指标

### 3.5 体系基线提示

- 某指标选中时，若文献基线带温度且选中体系存在该温度附近的数据点（|Δtemp| ≤ 50K，启发式阈值），图内提示「文献基准 @823K（虚线）与本体系 @823K 数据点可比」；否则提示「文献基准 @823K，与当前点温度差异大，谨慎对比」；基线无温度（temp 抽不到）时不显示可比提示

## 四、实验记录表单与巡检（worklog 结构 +1 字段）

### 4.1 数据结构

- `worklog.entries[].system?: string`（显式材料体系，自由文本）

### 4.2 表单

- 新建/编辑表单加「材料体系」输入（datalist 预设：SnSe、SnS₂、SnS、Bi₂Te₃、PbSe、MnTe、Cu₂Se、Ag₂Se、PEDOT/导电聚合物、碳材料、无机/有机复合，可自由输入）
- 列表展示：条目显示体系 chip（有则显示）

### 4.3 AI 巡检（triage）

- 巡检提示词加「材料体系」提取项；提取结果以 `system` 字段进入提案 diff（与 sampleId 平级）
- 提案面板 FIELD_LABELS.worklog 补 `system: '材料体系'`；已有记录补录体系：AI 巡检对无 system 字段的旧记录提取体系进提案（用户确认后落库），回填过程持续收敛 unrecognized
- 更新类提案应用逻辑无需改动（diff 直写字段）

## 六、成功标准（用户确认）

1. 单测全覆盖：单位换算表、工艺黑名单、多温度点全抽、体系字段优先/正则兜底各分支断言；原 20 条不回归
2. 样例数据验证：多温度 / 多体系 / 单位变体 / 工艺词干扰 / 无体系五种记录跑 buildMetricsSeries 输出符合规则（未识别不进图）
3. 面板浏览器实测：温度筛选切换、深浅区分 + 断线、空心点、警告条 + 点击补标注、tooltip 溯源
