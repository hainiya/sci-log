## 二、关键修复记录（过程中发现并解决的 bug）

1. **itemType 过滤重复前缀**：`itemType=journalArticle||itemType=conferencePaper` → Zotero 永远返回 0 条，Zotero 分支静默降级从未工作。修复为 `JOIN("||")`
2. **/state 漏 report 字段**：报告已生成但前端 state.report 永远 undefined。循环列表补 `"report"`
3. **镜像替换丢失增强字段**：syncZotero 全量替换时 fullText/AI 摘要被清空重解析。合并时保留
4. **failed 标记不重试 → 重试轰炸**：先修成 failed 也重试，再按报告要求加 failedAt 24h 冷却
5. **已解析条目 continue 拦死摘要生成**：无摘要+有全文的条目永远无法生成。修复为直接复用 fullText 生成
6. **同步请求超时**：手动补全 129 篇 × LLM 约 20 分钟。改异步后台任务立即返回
7. **PDF 解析依赖地狱**：pdf-parse 2.x（DOMMatrix）→ 1.1.1（动态 require fs）→ pdfjs v4/v6（fake worker 路径）→ pdfjs v1 lib（条件 require）→ **unpdf** 最终方案。教训：新依赖必须本地 esbuild bundle 验证后再进插件
8. **manifest allowedHosts 缺 api.openalex.org**：OpenAlex 请求被宿主拦截，0 写入。加白名单解决

## 五、已知边界

1. **Zotero 10 升级**：本地 API 引入 Zotero-Server-ID 与本地版 version 语义，同步需按新协议重写增量（不要把 version 当单调递增）
2. **Zotero 9.x 无写 API**：只读镜像 + 待整理批量 RIS 兜底（10+ 落地后退役）
3. **本地 API 无认证**：只读 + 本机访问，勿暴露 23119 端口
4. **深链兼容性**：zotero://select/library/items/ 依赖 Zotero 协议注册（Windows 偶发问题），降级显示 zoteroKey
5. **PDF 解析依赖宿主 resource.read**：file:// 读取失败时降级 failed（24h 冷却重试）
6. **ima / CAJ**：未接入 / 仅识别（CAJ 需专业工具）
7. **autoCollect 门槛**：基于标题-关键词命中，误杀/漏网边界由提案兜底
8. **LLM 成本**：翻译/生成按批限流（8 LLM/轮），全库铺完约 20 分钟
