## 1. 环境修复（前置，非方案项）

开工时发现三闸门全破，根因是宿主 SDK（openhanako）已不在本机，`@hana/*` 四个本地依赖为空目录：

| 现象 | 根因 | 修复 |
|---|---|---|
| `npm test` 2 失败（sources/import-parser） | `@hana/plugin-runtime` 空目录 → llm.js 无法加载 | 从 `~/.hanako/plugins/materials-research-copilot/node_modules/@hana`（完整安装副本）拷出四包 → `vendor/openhanako/packages/`，`package.json` 依赖改指 `file:./vendor/...`，`npm install` 重新链接 |
| `npm run typecheck` 2 失败 | `@hana/plugin-sdk`/`plugin-components` 无类型声明 | 同上（vendor 自带 `.d.ts`） |
| `npm run build:server` 失败 | esbuild 无法解析 `@hana/plugin-runtime` | 同上 |
| `import-parser.test` 1 失败 | `COL.content` 正则缺「内容」（内容列被当指标列） | 一行修复：`/^(content|备注|说明|内容|note|notes)$/i` |

**注意**：若 openhanako 源恢复，可把 `package.json` 依赖切回 `file:../openhanako/packages/*`，vendor 目录保留不冲突。

## 2. 后端 checkJs 类型化（O-5，585 → 0）

- 新增 `tsconfig.server.json`（`allowJs + checkJs`，extends 根配置）；`package.json` 的 `typecheck` 改为双闸门：`tsc --noEmit && tsc -p tsconfig.server.json`。
- 新增共享类型模块 `src-server/server/types.js`（JSDoc typedef）：`ToolCtx`（宿主上下文全字段）、`StoreApi`（read 以交叉签名表达 8 种文档精确返回类型）、`WorklogEntry`/`GanttTask`/`CalendarEvent`/`LiteratureEntry` 及各 StoreDoc。
- 23 个后端文件全部收敛到 0 错误，主要模式：
  - 函数参数/返回值 JSDoc（`@param`/`@returns`）——消除 ~300 个 TS7006；
  - `any.map(cb)` 显式 `/** @type {any[]} */` 转换——消除 noImplicitAny 回调报错；
  - `catch (err)` 统一 `err instanceof Error ? err.message : String(err)`——消除 TS18046/TS2339；
  - 宿主可选能力（`ctx.log/bus/config/network/stageFile`）修正为真实签名并可选链。

**checkJs 抓到的真实缺陷（类型化附赠价值）**：
1. `worklog-gen.js`：`export { parseDraft } from ...` 不创建本地绑定，`generateDraft` 内调用会在运行时抛 ReferenceError（已改为 import + re-export）；
2. `export-util`/`stageFile`/`bus.emit`/`sessionRef` 等宿主契约签名与代码实际用法不符（types.js 已按真实用法建模）；
3. `sources.js` OpenAlex 引用数补全：`entry.doi` 可能为 null 却直接拼 URL（新增 `if (!entry.doi) continue;` 守卫）；
4. `metrics.js`/`store.js`/`literature-log.js` 多处字面量对象与数据形状不一致（WorklogEntry 补齐 `kind/scanId/planVersion` 等可选字段）。

## 3. zod 边界校验（rust 文档方案 A 后半）

新增 `src-server/server/schemas.js`（zod v3，10 个 schema），按「请求体严格拒绝 / 动态边界观测容错」双原则落地：

| 边界 | Schema | 策略 | 位置 |
|---|---|---|---|
| LLM 输出（巡检） | `TriageOutputSchema` | 观测：safeParse 失败仅记日志，不改变既有容错 | `llm.js triageWorkEntry` |
| LLM 输出（日程建议） | `ScheduleItemSchema` | 观测 + 漂移条目过滤 | `llm.js nextStepAdvice` |
| 外部 API | `OpenAlexWorkSchema` | 观测：响应漂移记日志 | `sources.js enrichCitationCounts` |
| 请求体 ×6 | `WorklogImport`/`LiteratureAppend`/`SettingsMetrics`/`Binding`/`AutoTriage`/`SearchWindow` | 严格：结构不合法 → 400（错误语义保持：`empty_text`/`missing_targets`/`missing_sessionId` 等原样） | `routes/api.js` 六条路由 |

设计取舍（与 rust 文档 §4.4 一致）：LLM/外部 API 是「需要宽松容错」的动态边界，zod 只做观测不阻断，避免把健壮性改坏；store.read 不做每读校验（已有结构兜底 + version 归一化，重复解析是纯开销）。
